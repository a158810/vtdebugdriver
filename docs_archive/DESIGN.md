# LMvtdriver：SVM + NPT 第一阶段

## 边界与目标

- 首个验证平台是支持嵌套虚拟化的 AMD x64 Windows 虚拟机；虚拟机的处理器数量、处理器组布局、物理地址宽度和可用 SVM 能力必须在运行时枚举。
- 目标是一个由运行时枚举出的所有可用逻辑处理器参与、来宾为现有 Windows、NPT 同址映射、支持有序停止和卸载的常驻框架。
- 内存扫描、NPT Hook、隐藏、断点以及跨 Intel CPU 支持不属于这一阶段。
- 编译成功、单核 VMRUN 或一次 CPUID VMEXIT 不等于阶段完成；未通过带内核调试和快照的测试环境验证前不得在开发机上加载。

## 模块职责

| 模块 | 主要职责 |
| --- | --- |
| `svm_capability` | 检查 CPU 扩展叶、SVM/NPT、固件禁用位、物理地址宽度、已有 hypervisor；不支持即拒绝启动。 |
| `npt` | 管理四级页表及映射台账，按内存类型构建 GPA=HPA 初始映射，并预留 2 MiB 大页拆分接口。 |
| `svm_cpu` | 每个逻辑处理器独立的 VMCB、host-save 页、宿主栈、原始 MSR 和生命周期状态。 |
| `svm_entry` | 完整保存来宾通用寄存器，使用专用宿主栈处理 VMEXIT，从真实 Windows 上下文继续执行，并在停止时恢复原上下文。 |
| `svm_manager` | 根据运行时处理器枚举分配资源、同步启动所有目标处理器、汇总结果、失败回滚、退出确认和卸载。 |

## 生命周期

`Uninitialized → Prepared → Starting → Running → Stopping → Uninitialized`

1. 在启动任何 CPU 前完成各核资源分配及初始 NPT 构建。分配失败只释放尚未激活的资源。
2. 按运行时枚举到的处理器组和逻辑处理器索引寻址每个目标处理器，逐核记录进入结果；部分成功绝不能对外报告启动成功。
3. 一核启动失败，先让已经启动的核退出 SVM，再恢复各核原 MSR，最后释放共享 NPT。
4. 卸载必须让所有核确认已退出；只要某核可能继续引用 VMCB/NPT，就不能释放资源或卸载代码。
5. CPU 热添加、睡眠/休眠、已有系统 hypervisor 等未处理场景需要明确拒绝或阻止，不通过“暂不测试”默许支持。

## NPT 映射约束

- `nCR3` 指向页对齐的物理 PML4。初始页表准备完毕后才能在 VMCB 中设置 `NP_ENABLE`。
- 已确认的 RAM 使用合适的缓存类型；确认过的 MMIO 采用设备适用类型。不能把物理空洞不加区分地当作 WB RAM 映射。
- 同一缓存类型、完全覆盖且对齐的区间才能使用 2 MiB 项；边缘及混合类型使用 4 KiB 项。
- 页表页在来宾运行期间必须驻留。修改映射时要考虑逐核可见性及对应 TLB 刷新。
- NPF 日志至少包括逻辑处理器、GPA、退出信息和页表状态；不允许对未知物理地址盲目映射后无限重试。
- 所有页表项只允许使用 CPU 报告的物理地址位，保留位保持为零；内存加密位等平台差异须检测。

## 嵌套 SVM（L0/L1/L2）

- 第一阶段只支持单层嵌套：L0 驱动承载 L1 SVM 驱动，再承载一个 L2 guest；不支持 L3、多 VCPU、SEV/SNP、AVIC 或 L1 NPT。
- L1 执行 `VMRUN` 时，L0 从 L1 GPA 读取 VMCB12，经现有 L0 NPT 转换后复制到每个 VP 的临时 VMCB；L2 始终使用 L0 NPT 和 L0 的有效 MSRPM/IOPM。
- L1 的 VMCB GPA、MSRPM、IOPM、VM_HSAVE_PA 都必须页对齐并落在当前 L0 NPT 可访问范围内；非法地址、非法控制位、非法状态或启用 NPT 会向 L1 注入 `#GP(0)`，不会进入宿主崩溃路径。
- `VM_CR`、`IA32_EFER`、`VM_HSAVE_PA` 对 L1/L2 分别保存影子值。L0 永远保持自身运行所需的 `EFER.SVME`；L2 的 SVM 能力通过 CPUID 隐藏，并拒绝再次进入下一层嵌套。
- L1 的 EFER 影子值初始清除 `SVME`，其他位保留。L1 的 `RDMSR` 返回影子值，合法 `WRMSR` 可以开启或关闭影子 `SVME`；实际承载 L1 的 VMCB 始终保留 `SVME=1`，不改变 L0 的宿主 EFER。SVM 指令权限仍按影子值检查，L1 关闭 SVM 后不能继续执行嵌套 SVM 指令。
- L1 请求拦截的异常、CR/DR、CPUID、MSR、IOIO 及 SVM 指令退出会写回 VMCB12 后反射给 L1；L0 自己强制拦截的 CPUID/MSR/SVM 指令在未被 L1 请求时由软件完成。
- L2 的 NPF 不反射为 L1 NPF（当前不支持 L1 NPT）；已有的 L0 调试 NPT probe/watch 仍按原路径处理，其他未知 NPF 会终止本次嵌套并向 L1 注入 `#GP(0)`。其他未实现的 L2 VMEXIT 也安全注入 `#GP(0)`，不允许未知退出进入 `KeBugCheck`。
- VMCB12 回写包含状态保存区、退出信息、事件注入、NRIP 和指令字节；回写失败时结束嵌套状态并向 L1 注入 `#GP(0)`。

## 嵌套实现的安全边界

- `SvCopyNestedGuestPhysical` 只通过 L0 NPT 访问 L1 提供的 GPA，并逐页验证范围；不得直接把 L1 GPA 当作宿主虚拟地址使用。
- 物理地址检查按当前 L0 NPT 的 1 TiB 映射边界执行；后续若扩大 NPT 覆盖范围，必须同步调整嵌套地址掩码和验证逻辑。
- 驱动加载、嵌套 VMRUN、退出反射、卸载均必须在可回滚的 AMD Windows 虚拟机快照中验证，并准备 KD/蓝屏回滚路径。

## 原实验代码的边界

`vmmtostudy260921of1` 中的 `svm.c` 和 `AsmVmRun.asm` 可以用来对照 VMCB 结构和指令编码，但它们使用单套全局 VMCB、独立临时 guest 栈，执行 CPUID/HLT 后离开，不是 Windows 常驻 VMM；也没有建立启用的 NPT。不能通过复制它并添加 `NpEnable` 来满足上述目标。

## 验收

1. Debug x64 编译通过，VMCB 布局有静态断言，所有资源有明确所有者。
2. 在可还原的测试环境中，运行时枚举到的所有目标逻辑处理器独立报告成功进入；Windows 保持正常运行，无重复 NPF 或异常 VMEXIT 风暴。
3. 经进程/线程、内存、磁盘与网络负载后能正常停止；多次加载、停止、卸载，MSR 和资源计数回到基线。
4. 注入每个分配/启动失败点后能回滚；任何仍处于虚拟化状态的 CPU 不能释放其引用的页面。

测试和实现日志要区分“编译通过”“局部 VMEXIT 验证”“全核稳定运行”“可卸载”四个不同级别，不能混称为“跑通”。
