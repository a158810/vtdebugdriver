## 📋 项目概述

**项目名称**: LMvtdriver - SVM 虚拟化调试器  
**项目路径**: `E:\VSFILE\LMvtdriver`  
**架构**: 三层架构（Host Driver → Guest Driver → R3 Debugger）

### 核心技术
- **AMD SVM 虚拟化** - 使用 VMCB、NPT 进行虚拟机监控
- **DR3 硬件断点拦截** - 在 `KiDispatchException` 入口处拦截异常
- **CR3 过滤会话** - 针对特定进程的隔离调试
- **双工作模式**:
  - **Interactive Mode（交互模式）**: 断点命中时暂停线程，支持单步、寄存器修改
  - **Transparent Mode（透明模式）**: 记录异常事件但不暂停线程，隐蔽监控

### 项目组成
```
LMvtdriver/
├── LMvtdriver/              # Host Driver (Hypervisor 层)
│   ├── svm_core.cpp/hpp     # SVM 核心、VMEXIT 处理
│   ├── npt_manager.cpp/hpp  # NPT 管理
│   └── svm_entry.asm        # 汇编入口
├── LMvtdriverGuest/         # Guest Driver (虚拟机内核层)
│   ├── guest_driver.cpp     # IOCTL 处理
│   ├── guest_memory.cpp     # 内存读写（Host CR3 切换方式）
│   └── guest_probe.asm      # CPUID 调用汇编
├── LMvtdriverDebugger/      # R3 Debugger (用户态 GUI)
│   ├── MainDlg.cpp/h        # 主界面
│   ├── debugger.cpp/h       # 调试器核心逻辑
│   └── lmdbgr3.rc          # UI 资源文件
└── LMvtdriverGuestControl/  # CLI 控制工具
```

## 🔑 关键技术细节

### 1. Host CR3 切换内存读写
**优势**: 完全隐蔽，不调用 Windows API，不会被检测

**实现** (`svm_core.cpp:SvReadWriteVirtualMemory`):
```cpp
ULONG64 originalCr3 = __readcr3();
__writecr3(Cr3);  // 切换到目标进程的页表
__try {
    RtlCopyMemory(buffer, (PVOID)virtualAddress, length);
} __except(EXCEPTION_EXECUTE_HANDLER) {
    status = STATUS_ACCESS_VIOLATION;
}
__writecr3(originalCr3);  // 恢复原 CR3
```

### 2. Shared Page 通信机制
**Host 分配**: `svm_core.cpp:NptInitialize`
```cpp
g_SharedPage = (PLMV_SHARED_PAGE)ExAllocatePoolZero(...);
g_SharedPageGpa = MmGetPhysicalAddress(g_SharedPage).QuadPart;
```

**Guest 映射**: `guest_driver.cpp:LmvGuestQuerySharedPage`
```cpp
PHYSICAL_ADDRESS pa = { .QuadPart = pageResult.Magic };
g_SharedPage = (PLMV_SHARED_PAGE)MmMapIoSpace(pa, PAGE_SIZE, MmNonCached);
```

**通信流程**:
1. Guest 写入请求到 `g_SharedPage->Command.Argument0`
2. Guest 调用 `LmvGuestCpuidCall(commandId, ...)`
3. Host 在 `SvHandleCpuid` 中处理请求
4. Host 写入响应到 `g_SharedPage->Data[]`
5. Guest 读取响应

### 3. 透明模式事件流
```
异常发生 (Ring 3)
  ↓ DR3 断点命中
Host VMEXIT_EXCEPTION_DB (svm_core.cpp:2151)
  ↓ 检查 KiSessionMode
  ↓ if (LMV_DEBUG_MODE_TRANSPARENT)
Host 从 R8 读取 TrapFrame (切换 CR3)
  ↓
Host 记录到 HostEventQueue[tail]
  ↓ 原子递增 tail
Host 跳转到 KiSessionPassStub
  ↓ push rbp; vmmcall; ud2
Host 恢复到 KiDispatchException+2
  ↓ 线程继续运行，无感知
  
(定时器触发)
R3 调用 g_debugger.PollHostEvents()
  ↓
Guest IOCTL_LMV_GUEST_POLL_HOST_EVENTS
  ↓
Guest 调用 LmvCpuidCommandReadHostEvent
  ↓
Host 复制 HostEventQueue[head] → SharedPage.Data[]
  ↓
Guest 复制到输出缓冲区
  ↓
R3 调用 AddTransparentEvent() → ListView 显示
```

### 4. 模式切换机制
**当前实现** (`svm_core.cpp:1459-1495`):
- 使用 `LmvCpuidCommandSyncKiSession` 同步模式
- R3 → Guest (IOCTL_LMV_SET_DEBUG_MODE) → Host (CPUID)
- Host 从 `GuestContext->VpRegs->R13` 读取模式值
- 直接设置 `SharedVpData[cpu]->KiSessionMode`

**注意**: 模式应该在会话创建时设置，不应运行时切换

## 🔧 故障排查

### 常见问题

#### 1. 驱动加载失败
**症状**: `sc start LMvtdriver` 返回错误

**检查**:
```bash
# 查看驱动加载日志
dbgview.exe
# 或
driverquery | findstr LMvt
```

#### 2. 调试器附加失败
**症状**: "Failed to set debug mode" 或 "Attach failed"

**解决**:
- 检查 Guest Driver 是否已加载
- 确认 PID 正确
- 查看 DebugView 日志中的错误信息

#### 3. 反汇编显示 "cannot disassemble"
**症状**: 反汇编窗口无法显示代码

**原因**: 内存读取失败（已修复）

**验证**:
```cpp
// 检查 DebugView 日志
[!] Disassemble: ReadMemory failed at 0x... (error 299)
```

#### 4. 透明模式事件列表为空
**症状**: 附加后事件列表没有更新

**检查**:
1. 确认模式已设置为"透明模式"
2. 检查 500ms 定时器是否启动
3. 验证 Host 的 `HostEventQueue` 是否有数据
